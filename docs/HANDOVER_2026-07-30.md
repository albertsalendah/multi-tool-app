# Current Problem

Workflow Engine is halfway through a redesign.

Current issue:

workflow.py now uses

```
WorkflowState
```

while

workflow_engine.py

still references

```
workflow.context
```

These are inconsistent.

ParallelGroup also currently stores

```
list[WorkflowStep]
```

It should store

```
list[WorkflowNode]
```

to allow future nested nodes.

This should be the LAST architectural change.

├── WorkflowStep
│
├── ParallelGroup
│

Only

- WorkflowStep
- ParallelGroup

need to be implemented now.

The other node types are reserved for the future.

# Design Decisions

ExecutionContext

represents

ONE tool execution.

WorkflowState

represents

ONE workflow execution.

Never mix the two.

---

Workflow API

Preferred syntax

```python
wf = Workflow("Example")

wf.add_step(
    "download",
    url="...",
    result_as="download",
)

with wf.parallel():

    wf.add_step(
        "ocr",
        image="{{download.image}}",
        result_as="ocr",
    )

    wf.add_step(
        "compress",
        input="{{download.file}}",
        result_as="zip",
    )

wf.add_step(
    "upload",
    archive="{{zip.file}}",
)
```
